# 收银页改造：每日汇总 + 订单卡设计

日期：2026-09-30 · 分支：lifehall · 状态：已获批

## 一句话目标

把收银页从「单笔录入表单 + 扁平流水表格」改成「吸顶录入 + 每日汇总 + 每笔订单一张卡
（卡内编辑）」，布局参考华为 POS 截图（左数据右信息栏），并加一键导入玲珑销售单。

## 背景与方向

- 用户 2026-09-30：「优化收银页面，参考这个界面」（华为 POS 截图：左扫码右信息栏）。
- 中途转向：「我们要做的是每天的汇总，不是单笔录入」——页面主体从录入表单让位给
  当日汇总与订单卡列表；录入区收窄为吸顶的一小块。
- 实现路线（已选定 **方案 A**）：原地重排 `#subpanel-cashier`，不抽 iframe、不改
  后端接口形状；功能微调（SN / 配件 / 组合支付 / 玲珑导入）另列。

## 布局总览

自上而下三段，**前两段吸顶**，只有卡列表滚动：

```
┌──────────────────────────────────────────────┐
│ ① 顶部录入区（吸顶）                            │
│  [扫码或输入商品编码 ………………… OK] [刷新政策数据]   │
│  时间[现在] 名称[] 数量[1] 实收[] SN[] 销售员[]    │
│  备注[] [保存一笔]                             │
├──────────────────────────────────────────────┤
│ ② 当日汇总条（吸顶）                            │
│  日期 今日 N 笔 · X 件 · 实收 ¥A · 配件 ¥B       │
│  [导入玲珑单] [排除关键词] [日期 ◂ 今天 ▸]        │
├──────────────────────────────────────────────┤
│ ③ 订单卡列表（滚动区）                           │
│  ┌─ 卡片 ──────────────────┬─ ✕（右侧垂直居中） │
│  │ 左区：商品明细           │ 右区：销售信息…      │
│  └────────────────────────┴───────────────┘ │
└──────────────────────────────────────────────┘
```

- **吸顶**：①② 用 `position: sticky`（或固定顶栏），③ 滚动时不动。
- 纯前端布局重排；**所有 `#cashier-*` id 保留**，事件绑定与
  `cashierSave/cashierLookup/cashierRemove` 复用。
- 不做响应式断点（门店固定分辨率宽屏）；卡内右区在窄宽度下允许折行兜底。

## 顶部录入区（新录一笔专用）

- 第一行：**大扫码框**（全宽主角，回车反查、失焦反查的现有交互不变）+
  右端「刷新政策数据」按钮。
- 第二行：`销售时间`（默认现在）`商品名称`（反查带出，可手补）`数量`（默认 1）
  `实收`（必填，反查后光标自动跳入）`SN`（可空，手输或扫码枪再扫一次）
  `销售员`（datalist）`备注` `[保存一笔]`。
- **不做**商品码 / SN 的自动识别区分——两个独立输入，SN 可空。
- **反查提示行取消**（用户 2026-09-30：「反查提示没必要」）：查不到时 toast 报错；
  价格/返利信息不在页面展示。
- 保存校验不变：实收必填、非数字/负数拦（后端 `_clean_entry`）。

## 当日汇总条

- 左：`日期 · 今日 N 笔 · X 件 · 实收 ¥A · 配件 ¥B`。
  - 笔数 = 当日卡数；件数 = Σ数量；实收 = Σamount；配件 = Σ配件金额（**不并入实收**）。
  - 数字前端由 rows 现算，不加接口。
- 右：`[导入玲珑单]` `[排除关键词]` `[日期 ◂ 今天 ▸]`（日期切换从原流水卡标题挪来）。

## 订单卡（一卡一笔）

左右两区；编辑在卡内完成（不再回填顶部表单）：

```
┌──────────────────────────────┬─────────────┐
│ 14:32                        │ ▌销售信息     │
│ MatePad Air 12.2             │ 销售员 [张三▾] │
│ 商品编码 6901234567890       │ 备注  [老客户…]│
│ SN   HXR1234567890           ├─────────────┤
│ 数量 1                        │ ▌客户信息(灰) │
│                 实收 ¥1899    │ 会员/手机号   │
│ ▌配件区                      │  → 待接入     │
│   原装保护壳     ¥199         ├─────────────┤
│   + 添加配件                  │ ▌支付方式     │
│ [保存修改] [取消]            │  见下节       │
└──────────────────────────────┴────── ✕ ────┘
```

- **左区竖排**：① 时间 → ② 商品名称 → ③ 商品编码 → ④ SN → ⑤ 数量（左）+
  **实收金额右对齐大字** → ⑥ 配件区。
- **配件区**：多条 `{配件名, 金额}`，可增删；金额**不并入**实收。
- **右区**：上段「销售信息」= 销售员 + 备注（真字段）；下段「客户信息」「支付方式」
  分组标题（蓝竖条，参考图样式），客户信息整块置灰标「待接入」。
- **卡内编辑**：非编辑态左下只有「改」按钮；点「改」→ 卡片变编辑态（字段变输入框，
  底部 `保存修改 / 取消`），走同一 `POST /api/cashier/entry-save`（带 `id`）。
  删除**只有右侧 ✕ 一个入口**（不重复放「删」按钮）。正在编辑的卡加高亮边框。
- **组合支付**（卡内右区）：
  - 每个支付方式一个小方块（方式名 + 下方金额输入框），右上角 ✕ 删块，
    底部「+ 添加支付」加块。
  - 底部实时 `已付 ¥X / 应付 ¥Y`，**不一致黄条软提醒，不拦截保存**（用户定：
    入后端 + 软提醒）。
  - 支付方式清单**写死在前端**（照用户截图：助手 / C扫B / POS / 现金 / 公对公 /
    以旧换新 / 预收款 / 企业微信 / 支付宝直连 / 微信直连…），**存原始字符串**
    （清单以后增删不坏老数据）。
- **卡片右侧垂直居中 ✕**（用户 2026-09-30）：两类卡统一位置、语义分叉——
  - 手工卡（`source=manual`）：✕ = 删流水，沿用 `entry-delete` + 确认弹窗；
  - 玲珑卡（`source=linglong`）：✕ = **当日视图排除**（软排除标记，不删 dump 库
    `orders`，再导入也不会加回来）。

## 一键导入玲珑销售单

汇总条按钮，流程：

1. 调 CBG 接口拉**当天**销售单（复用 `dump.list_all_orders` 通道；
   会话掉了走现有弹窗人工登录，同「刷新政策数据」）。
2. 合并进 `out/cbg-<年>.db` 的 `orders`/`order_lines`：按 `document_no`
   幂等 upsert，已有就更新。
3. 当天单据 → `sale_entries`（`source='linglong'`，`external_id=document_no`
   唯一约束）：**单据一卡**，多行聚合——数量=Σ行数量、金额=单据实付、
   商品名=首行名（多行显示「… 等N件」）、编码拼接。
4. **过滤两道**：
   - 备注命中**黑名单关键词**的单据跳过；
   - `external_id` 已存在（含已软排除）的跳过——重复点不重复入卡。
5. **黑名单页面可设**：汇总条「排除关键词」→ 行内输入（逗号分隔），
   存 `.secrets/cashier-import.json`（本机配置，selfupdate 不碰），改完立即生效。
6. 错误处理：接口/网络失败 toast 报错；已完成的合并不回滚（幂等，可重按）。
7. 玲珑卡可卡内编辑：改的是 `sale_entries` 行，**不动 dump 原单**；卡上小字
   标「原单号 XXX，修改只影响本机视图」。

## 后端改动（`src/features/cashier/store.py` 等）

- `sale_entries` 迁移补列（SQLite ALTER，老数据不回填、读时兜底）：
  - `sn` TEXT
  - `accessories` TEXT —— JSON `[{"name":…,"amount":…}]`
  - `payments` TEXT —— JSON `[{"method":…,"amount":…}]`（method 存原始字符串）
  - `external_id` TEXT —— 玲珑 `document_no`，唯一索引（手工单为 NULL）
  - `excluded` INTEGER —— 玲珑卡软排除标记（0/1）
- `save_entry` 收 `sn/accessories/payments`；校验规则不变（实收必填、非负）。
  支付加总 ≠ 实收**后端不拦**。
- `list_entries(day)` 带出新字段；**排除 `excluded=1`** 的行。
- 新增：
  - `import_linglong(root, day)` —— 拉单 → upsert orders → 生成 entries →
    返回 `{imported, skipped_blacklist, skipped_dup}`；
  - `exclude_entry(root, id)` —— 玲珑卡软排除；
  - 黑名单读写 `load_blacklist/save_blacklist`（`.secrets/cashier-import.json`）。
- `web.py` 新增路由：`POST /api/cashier/import`、`POST /api/cashier/exclude`、
  `GET/PUT /api/cashier/import-settings`——**照现有 `/api/cashier/*` 块接**，
  前缀门禁（role != store 403）自动覆盖。

## 前端改动

- `index.html`：`#subpanel-cashier` 重排为 录入区 / 汇总条 / 卡列表；
  id 全保留，新增卡容器与设置弹层的 id。
- `app.js`：`renderCashierTable` → `renderCashierCards`；新增卡内编辑、
  配件增删、支付方块增删与合计提醒、导入按钮、黑名单设置、✕ 删除分流。
  汇总数字由 rows 前端现算。
- `style.css`：收银页专属布局（sticky 顶区、卡片两区 grid、参考图风格蓝竖条
  分组标题、支付方块彩色块）。

## 本版不做

- 客户信息真接入（保持置灰占位）。
- 独立页 / iframe（方案 B 已否）。
- 商品码 vs SN 扫码自动识别。
- 支付方式清单后端可配置。
- 响应式断点 / 移动端适配。
- 配件金额并入实收合计（分开记，以后要并再改）。
