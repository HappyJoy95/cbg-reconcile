# 2026-09-30 收银订单卡 · 开发目标

## 一、一句话目标

收银页从「单笔录入表单 + 扁平表格」改成「吸顶录入 + 当日汇总 + 订单卡（卡内编辑）」，
并加一键导入玲珑销售单。

## 二、已定的

布局 / 字段 / 导入 / 删除语义**全部见已获批 spec**：
`docs/superpowers/specs/2026-09-30-cashier-cards-design.md`（五节设计 + 后端/前端/测试/不做）。

核心已定项（spec 摘要，细节以 spec 为准）：

1. **方案 A**：原地重排 `#subpanel-cashier`（三段：吸顶录入 / 吸顶汇总条 / 卡片滚动区），
   不抽 iframe —— 方案 B 已否。
2. **卡内编辑**：编辑在卡片里完成，不再回填顶部表单；删除只有右侧 ✕ 一个入口。
3. **两类 ✕ 语义分叉**：手工卡（`source=manual`）= 删流水；
   玲珑卡（`source=linglong`）= 当日视图**软排除**（不删 dump 库，再导入也不回加）。
4. **一键导入玲珑销售单**：复用 `dump.list_all_orders` 通道 → 按 `document_no`
   幂等 upsert → 单据一卡（多行聚合）→ 黑名单 + `external_id` 去重两道过滤。
5. **黑名单页面可设**：逗号分隔关键词，存 `.secrets/cashier-import.json`，改完立即生效。
6. **组合支付入后端 + 软提醒**：已付 ≠ 应付黄条提醒、不拦保存；支付方式清单
   写死前端、存原始字符串。
7. **配件金额不并入实收**（分开记，汇总条单独一列）。

## 三、边界（含项目红线）

- 方案 A：原地重排 `#subpanel-cashier`，**不抽 iframe**；
- **后端接口形状不破坏**：现有 `/api/cashier/*` 五个路由
  （`entries` / `entry-save` / `entry-delete` / `lookup` / `policy-refresh`）行为不变，
  新路由（`import` / `exclude` / `import-settings`）照现有块接、前缀门禁自动覆盖；
- 测试必须传 `root=` 临时目录；`.secrets/` 只写 `cashier-import.json`；
- Python 3.8 兼容（不用 `match`、不用 `X | None` 运行期注解）；
- 不 commit / push / 打包 / 升版本号 —— 攒着，等用户说「推吧」。

## 四、里程碑

1. **后端**：迁移（`sale_entries` 补 `sn`/`accessories`/`payments`/`external_id`/`excluded` 列）
   → 字段存取 → 黑名单/排除 → 导入（各自独立可测）。
2. **前端**：HTML/CSS 重排 → 卡片渲染 + 卡内编辑 → 导入/黑名单 UI。
3. **全量回归**（三头 pytest 全绿）。

## 七、风险

- **导入是网络操作**：会话失效要给人话（走现有弹窗人工登录，同「刷新政策数据」）；
- **前端改动面大**：`app.js` 收银段整段重写 —— `node --check` + 接线测试必须绿；
- 支付加总 ≠ 实收**后端不拦**（用户定的软提醒），别顺手加成硬校验。

## 八、本版不做的

见 spec「本版不做」，逐条收口：

- 客户信息真接入（保持置灰占位标「待接入」）；
- 独立页 / iframe（方案 B 已否）；
- 商品码 vs SN 扫码自动识别（两个独立输入，SN 可空）；
- 支付方式清单后端可配置；
- 响应式断点 / 移动端适配；
- 配件金额并入实收合计（分开记，以后要并再改）。
