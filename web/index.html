月度生意计划

本月是「当月 1 号 ~ 数据截至日」，上月同期是「上月 1 号 ~ 上月同一天」 （同天数，遇到上月没那一天就取到月底）。
环比 =（本月 − 上月同期）/ 上月同期；上月为 0 写「新增」、 上月为负或两边都是 0 时不给百分比（显示「—」）。
利润取云商「零售考核毛利」。销量含退货（源数据里已是负数，直接相减）。
剔除：核销 / 客情单等非零售单据、演示机 / 体验机、串号标识含「外调」的行； 名单外的店（联想专卖店 / 部门 / 机场店）一条都不算。
⚠ 这是「按串号卖出去的」口径（跟四池对账同一份数据）， 不是云商全部开单 —— 无串号的行（配件、第三方耳机等）不在内。
⚠ 展开后看到的是系列 / 机型，它们的数**加不出**上一层的合计 （同一台机器只在一个机型里，但层级行都在表里）—— 要合计看最左边那一列。

月度 POS 合规率

官方口径（跟财经那份成绩同一个算法）： POS使用率 = 1 −（现金 + 记账）/ 总金额， 先按天算、再取统计期日均值。
「现金」= 开钱箱的收款方式；「记账」= 渠道名为「记账」的（如公对公打款）。
官方的「不含退货数据」= 退货要扣掉（算净额，在退货发生当月扣、 原单当月不动）—— 两个口径都扣。
两个口径并排：「按标签」认 orderLabelList、「按备注」认 remark == '国补' —— 实测两者会不一致，所以两个数都要看。
我们自己的口径（表格里「我们」那两列，留着跟历史报表对账）： 分子 = 非现金支付、分母 = 全部金额，退货在退货当月扣减，整月汇总。
⚠ 两边都排除国补 / 即时零售 / Care+：那几类在我们库里全走现金， 不排除会被补贴砸掉几十分（实测国补占支付额 54%）。
⚠ 官方公式里的「异常金额」（成交价低于建议零售价 30% 以上的部分） 暂时没有数据源（要建议零售价，库里只有成交价）⇒ 按 0 计， 这一项会让官方分数比这里算的略低。
⚠ 暂定：最近两个月 —— 上月成绩在下月 15 日内才定稿。

推送记忆

双平台数据对比推送会记住"这个串号推过没有"：第一次出现标 ★ 新， 之后再出现就弱化，并写上"已推 N 次、首次几号"。
因为批发单那种情况（云商先报、玲珑过后才报）会连着推好几天， 全是重复的，门店看两天就麻木了。
什么时候用它：想让清单里每一条都重新醒目一次的时候点一下 —— 它不会让任何一条少被提醒。
⚠ 一般用不着手动清：串号从清单里消失（报量了 / 出库了）时会自动忘掉。
⚠ 清空之后，下次推送会把当时清单里的每一条都重新当"新的"强调一遍。

防护膜达成情况

新机 =（手机零售净台数 + 分销里备注含「美团」净台数）× 0.9； 京东分销、其它分销不算。
达成 = 贴膜去掉高透软膜，零售+分销（含退）净件数，不含核销。
目标 = 新机 ÷ 2；跟机率 = 达成 ÷ 新机； 毛利目标 = 新机 × 台均基线（25/30/35/40，按店）。
礼包只算 9 个膜类礼包品名；总达成率 = 毛利达成率×50% + 礼包达成率×50%。
点门店名拆到个人：同一套公式按个人新机台量推目标（基线仍是本店档）； 人加总 = 店里那一行。
