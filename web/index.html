月度 POS 合规率

口径：分母 = 非国补、非即时零售、非 Care+ 的订单金额 （团单保留，它走单独申诉）； 分子 = 其中的非现金支付金额（微信/支付宝/花呗/刷卡…只要是现金以外都算）。
退货：在退货发生当月扣减原单的金额与非现金部分。
两个口径并排：「按标签」认 orderLabelList、「按备注」认 remark == '国补' —— 实测两者会不一致，所以两个数都要看。
⚠ 暂定：退货在退货当月扣减 ⇒ 上一个月的分数还会被这个月的退货改， 所以最近两个月标暂定，等它过完才定稿。

出问题了？

    

      
      
      
      
    

    

    
    

      上报 bug：点一下会把现场日志打包（执行日志 / 定时任务 / 配置 / 环境），
      然后试着发到邮箱和企业微信。

      ⚠ 包里没有任何能拿去登录的凭据（.secrets\ 整个不进包），
      但有业务数据（门店名 / 串号 / 金额），发之前确认收件人是自己人。

      ⚠ 发不出去也不影响 —— 包会留在 out\report-bug-时间.zip，
      界面上会把路径写出来，直接把这个文件发出去就行。
      「推送失败」本身就是最常见的 bug，用它来上报它自己当然也不行。
    

    

      清除推送记忆：四池对账推送会记住"这个串号推过没有" ——
      第一次出现标 ★ 新，之后再出现就弱化并写上"已推 N 次、首次几号"。

      原因是批发单那种情况（云商先报、玲珑过后才报）会连着推好几天，
      全是重复的，门店看两天就麻木了。

      ⚠ 清空之后，下次推送会把当时清单里的每一条都重新当"新的"强调一遍。
      串号从清单里消失（报量了 / 出库了）时会自动忘掉，一般用不着手动清。

      所以它是"反过来"用的：想让清单里每一条都重新醒目一次时才点 ——
      它不会让任何一条少被提醒。
    

  


  

    
定时执行

    


    

      
      
      
      
    

    

      「抓四池数据」每次都会跑，不用选、也取消不掉 ——
      不抓的话本地库永远是旧的，POS 和四池对账都只是拿旧数据在算，
      而界面上只会显示"跑完了"。

      「四池对账」要勾着才会算 AD/BC 并推送 —— 它读的是云商和玲珑两边的快照，
      不勾的话那两份清单永远不会出来。

      「POS 合规」不勾就不算当月的合规率，「POS 合规」页会停在上次算出来的数。

      两个都不勾也允许：那就是「每天只抓数据，不算也不推」。

      改这里不用重新注册任务，也不用弹 UAC：计划任务跑的是 run.bat，
      改的是它的内容，任务本身没变。
    


    

      
      
      
      
    

    
建议设在店里肯定开着机的时候（比如关门前）——
      Windows 计划任务错过时间不会补跑。

      每行右边的「执行」会立刻按这条任务跑一次（跟到点自动跑走的是同一条路，
      所以顺手能验证任务配得对不对）；「删除」只删那一行。

      开机自启那个任务不在这张表里，在「后台服务」卡片管。
