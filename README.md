# cbg-reconcile · 云商 ↔ 华为报量对账

> **解决什么问题**：B 店卖了 A 店的货，货挂 A 店名下，**A 店必须向华为报量**。
> 但 A 店往往不知道自己的货被谁卖了、报了没有。
> 这个工具每天早上在门店电脑上自动比对一遍，把**「云商已经卖了、华为还没报量」的串号**列出来。

设计文档：[`../docs/superpowers/specs/2026-09-15-cbg-reconcile-design.md`](../docs/superpowers/specs/2026-09-15-cbg-reconcile-design.md)

---

## 快速开始（本机）

```bash
cd cbg-reconcile
python3 -m src.cli serve            # → http://127.0.0.1:8787
```

门店电脑上双击 `start.bat` 即可 —— 它会**把服务放后台跑**，
前台窗口报完「启动成功」按任意键就关掉，**服务继续在后台**。停止用 `stop.bat`。

```bash
python3 -m src.cli status           # 服务在不在（退出码 0 = 在跑）
python3 -m src.cli status --wait 20 # 等它就绪（start.bat 用的就是这个）
python3 -m src.cli stop             # 停掉后台服务
python3 -m src.cli serve --no-open  # 前台跑（调试用）
```

打开 **会话** 页 → 填「**华为账号 / 密码**」→ 点「**打开浏览器抓取**」。

工具会用自己的浏览器 profile 打开门店日常入口
（`https://cbg.huawei.com/#/group/smart-store/homepage`），没登录会自动跳到华为 SSO，
然后**自动填表登录**、把 cookie 抓走 —— 不用手点，也不用抄 curl。

不填账号密码也能用：那样会打开窗口等你手动登一次。

纯命令行等价写法：

```bash
python3 -m src.cli auth --auto      # 打开浏览器，登录一次
python3 -m src.cli check --days-ago 1
```

产出：`out/差异_<目标日>_<门店码>_<生成时刻>.xlsx`，5 个工作表
（未报量 / 反向差异 / 已报量 / 过滤统计 / 运行信息）。

**每次跑都存一份，永不覆盖** —— 同一个目标日跑多次会得到多个文件，
因为"上一次跑出来是什么样"往往正是要对比的：

```
差异_2026-09-14_SCN231409_20260915-090012.xlsx   ← 计划任务跑的
差异_2026-09-14_SCN231409_20260915-113045.xlsx   ← 发现不对手动又跑了一次
```

控制台「报告」页可以**逐份删除**（连同摘要 json 一起删），点一下带确认。

**退出码**：`0` 正常 · `1` 会话过期 · `2` 取数失败 · `3` 有差异（计划任务可据此判断）

> 只需要 `requests pyyaml openpyxl` 三个包 —— 自动抓 cookie 用的是标准库实现的
> CDP 客户端（`src/cdp.py`），**没有引入 Playwright / Selenium / websocket 库**。

## 会话怎么来（自动抓，不用手抄）

```
python3 -m src.cli auth --auto      # 打开浏览器窗口，登录一次（首次 / SSO 过期时）
python3 -m src.cli auth --refresh   # 无头静默续期，不弹窗（日常自动用这个）
```

原理：**让我们自己启动的浏览器把 cookie 交出来**，不去解密浏览器的 cookie 数据库
（Chrome 127+ 有 App-Bound 加密，版本一升就废，不能依赖）。

| 要的东西 | 从哪拿 |
|---|---|
| cookie | CDP `Network.getAllCookies`（明文，官方接口） |
| `x-csrf-token` | CDP 在 cbg 页面上执行 JS 读 `localStorage['pix-environment-csrf-token']`；读不到再退回去调 `phoenix-gws/phoenix.sso.csrf.token` |

> csrf 的来源是从平台引擎 `app.*.min.js` 里挖出来的：
> `$PIX.Util.localStorage.set("pix-environment-csrf-token", a)` —— 前端就是这么存的。

**日常怎么做到不用管**：工具用**自己的浏览器 profile**（`.secrets/browser-profile`）。
里面的 SSO 登录态能活很久，所以 `check` 发现会话失效时会**自动开一个无头浏览器**
把新 cookie 取回来 —— 全程无人工。只有 SSO 本身过期了才需要再点一次「打开浏览器登录」。

**隐私边界**：只读我们自己启动的那个 profile，**不碰店员日常用的浏览器**。

> **打包时的默认值**：云商账号密码带上（业务要求）；
> 华为账号、邮箱授权码、企微 webhook **一律不带**，到门店在界面上填。
> 它们都是即时可撤销的，而云商账号是跑起来的前提。

### 两条安全设计（都踩过）

1. **验证通过才落盘**。浏览器里可能躺着一份过期的 cookie —— 名字齐全但根本用不了。
   所以抓到的凭据必须先过 `ping` 自检，**没过就继续等，绝不覆盖现有会话**
   （否则一次失败的续期会毁掉一个还能用的会话）。
2. **未登录时 cbg 也会发 `JSESSIONID`**。所以「cookie 名字齐了」根本不能当判据，
   只能靠自检 —— 这就是上面第 1 条存在的原因。

### 华为账号密码（自动登录）

存在 `.secrets/huawei.env`，界面上填、**不回显**。配了之后：

* `auth --auto` / `auth --refresh` 都会自动填表登录
* **`check` 也会用** —— 会话文件缺失或已过期时，自动起无头浏览器、
  用账号密码登录、抓回 cookie 再继续。**按需触发**，会话还能用就不起浏览器。
  全新门店电脑上（连会话文件都没有）第一次跑就能自己把会话建起来。

⚠ 两种情况下会**停止自动重试**并转人工，因为硬试的代价更大：

| 情况 | 为什么停 |
|---|---|
| 登录页出现**图形验证码** | 自动过不了 |
| 登录页**已报错**（账号密码不对等） | 再试就是往同一个账号上连打失败登录，**可能锁号** |

入口 URL 以**门店日常入口**为准（配置里的 `session.login_url`）：
未登录时它自己跳 SSO，所以**不去硬编码登录地址** —— 换域名/换 SSO 版本不用改代码。

实测登录页（`uniportal.huawei.com/uniportal1/login-pc.html`）只有三个控件：
`#username`、`#password`、一个「记住用户名」复选框，提交按钮是文字「登录」的 button。
**没有验证码输入框**。

⚠ 两种情况下自动登录会停下、改成等人工：

* 登录页出现**图形验证码**（连续失败几次后会出现）
* 自动登录试了 3 次仍不成功

停下时窗口会留着，你在窗口里手动登完，cookie 照样会被自动抓走。

> 填表的技术点：直接改 `.value` **不会触发 Vue 的响应式**，必须走原型链上的原生
> setter 再派发 `input`/`change` 事件。密码用 `json.dumps` 转义后注入，不手拼字符串。

### 退路：手抄 curl

浏览器装在不常见的位置、或者自动抓取被安全软件拦了，就走这条路：

1. 浏览器打开 `https://cbg.huawei.com/`，进新零售/报量页面
2. `F12` → **Network** → 刷新页面
3. 找任意一条发往 `cbg.huawei.com`、返回 JSON 的请求
4. 右键 → **Copy** → **Copy as cURL (cmd)**
5. `python3 -m src.cli auth --from-curl curl.txt`（界面上也能粘）

## 本地控制台

```bash
python3 -m src.cli serve              # 默认 127.0.0.1:8787，端口占用会自动换
python3 -m src.cli serve --port 9000  # 指定端口
python3 -m src.cli serve --no-open    # 别自动开浏览器
```

**只监听回环地址** —— 这是能改配置、能触发对账的本地管理工具，不该暴露到局域网。

| 页签 | 能干什么 |
|---|---|
| **报告** | KPI 卡片（未报量/已报量/反向）· 历史报告列表 · 点开看五个工作表 · 下载 xlsx |
| **运行** | 一键跑（昨天/今天/指定日期，可调时间窗容差）· **实时日志** · 跑完自动刷新报告 |
| **会话** | 当前会话状态 · **自动抓 cookie**（打开浏览器登录一次）· 抓 curl 的退路 |
| **设置** | 门店三行配置 · **云商账号**（含「测试登录」换 token）· **邮件推送** · **企微群推送** · **后台服务 / 开机自启** · 对账参数 · **定时执行**（任务列表 + 逐行删除） |

技术选择：**Python 标准库 HTTP 服务 + 无构建的原生前端**，不引入 Flask / Node / CDN。
门店电脑只用装 `requests pyyaml openpyxl` 三个包，断网也能用。

### 云商账号在界面上配

不用去改 `.secrets/erp.env` 文件了。「设置 → 云商账号」填账号密码，点「**测试登录**」：

* 真去云商换一次 token，成功会回显**登录人**（证明 token 真能用，不只是"登录接口返回 0"）
* **测试失败不落盘** —— 打错一个字母不会把好密码覆盖掉
* 只有**账号或密码真的变了**才作废旧 token；只改公司代码、或重复点保存，token 不受影响
* 密码**永不回显**（界面只知道"配了没配"）
* 万一账号要图形验证码，有「手动填 token」的退路

> ⚠️ **别连着点「测试登录」** —— 云商连着登几次会开始要求图形验证码。

### 云商要图形验证码？

**会直接显示在页面上**，照图填一下就行，不用去浏览器 F12 抄 token：

```
云商要图形验证码 —— 照着下图填一下即可（这是云商的，不是华为的）
[验证码图]  [填图上的字]  [提交验证码]
看不清就再点一次「测试登录」换一张。
```

填错会自动换一张新图，让你重填。

命令行也一样（`python -m src.cli erp-login`）：会把图存到 `out/云商验证码.png`
并在终端问你一次；不是交互终端就提示你去控制台填。

> 协议来自已经跑通的浏览器端实现（`Inventory Check/src/erp.js`）：
> `POST api/User/Login` 表单参数 `{token:'', userName, userPwd, VCode?}`，
> `ResponseID=2` 时 `Data` 就是 `data:image/png;base64,...`。
> **参数名必须正好是 `VCode`**。

### 邮件推送

**默认关着**，配好再打开。每次跑完把差异清单（xlsx 附件 + 正文摘要）发到指定邮箱。
「设置 → 邮件推送」配：

* 从「常见邮箱快速填充」选一个（QQ / 腾讯企业邮 / 163 / 阿里 / Outlook），自动填服务器端口
* 账号 + 密码（**多数邮箱要填授权码，不是登录密码**）
* 收件人：多个用逗号分隔
* 「发送时机」：`每次都发`（默认）或 `只有差异才发`
* 点「**发送测试邮件**」验证 —— **失败不落盘**

主题一眼能看出结果：`[报量对账] 青岛新业广场店 2026-09-14 · ❌ 未报量 2 台`

**发邮件失败不会让对账失败**。对账结果是主产物，邮件只是投递方式 ——
邮件挂了要大声说（stderr + 日志），但退出码不受影响，差异清单照样出。

命令行：`python -m src.cli mail-test` 发测试邮件；`check --no-mail` 本次不发。

> 实测坑：`smtp.qq.com` 有 IPv6 地址但那条路会卡死，所以发信**强制走 IPv4**。

### 企微群推送

**默认关着**，配好再打开。每次跑完推送到企业微信群机器人。「设置 → 企微群推送」配：

1. 群里 → 右上角设置 → **群机器人** → 添加机器人 → 复制 **webhook 地址**
2. 粘进「webhook 地址」（整条粘进来，含 `key=…`）
3. 点「**推送测试消息**」验证 —— **失败不落盘**

| 开关 | 说明 |
|---|---|
| 有差异时 @所有人 | 企微 **markdown 不支持 @**，所以会**另发一条 text** 带 `mentioned_list`，再发 markdown 详情 |
| 同时把 xlsx 传到群里 | 走 `upload_media` 换 media_id 再发（限 20MB） |
| 发送时机 | `每次都推` / `只有差异才推` |

**webhook 地址当凭据存**（`.secrets/wecom.env`）—— 拿到它就能往群里发消息，性质等同密码。

> ⚠️ 企微限流**每分钟 20 条**。一次推送最多 3 条（@文本 + 摘要 + 文件），不用担心。

命令行：`python -m src.cli wecom-test` 推测试消息；`check --no-push` 本次不推。

**企微推送失败同样不影响对账**。

## 部署到门店电脑（Windows）

### 最快路径

发**正式包**（`dist/*.zip`），**别让门店 clone 仓库**。四步：

1. 解压到 `D:\cbg-reconcile`（路径**别带空格**、别放桌面）
2. 双击 **`install.bat`** —— 装依赖，然后问一句要不要开机自启（回车即开）
3. 双击 **`start.bat`** —— 打开控制台（<http://127.0.0.1:8787>）
4. 在控制台里配完：**门店那三行** → 云商账号 → 邮件 / 企微 → 会话页抓一次登录
   → 设置页加定时任务

> 顺序上只有一条铁律：**先把门店配对，再加定时任务**。反了的话到点那一跑
> 会拿别的店去对账，而且**看起来一切正常**。

> 装了 git 的机器（开发机、测试机）也可以直接 `git clone` 之后双击 `install.bat`，
> 见 [运维手册](运维手册.md) 里的「clone 部署」。
> **但门店建议用正式包** —— 两条路的差别在那儿写清了。

完整步骤、每一步的界面在哪、出问题怎么办：
**门店看 [门店操作手册](门店操作手册.md)**（五六步的那种）；
部署 / 排查问题看 **[运维手册](运维手册.md)**。

下面 1~8 步是**手工做法** —— 正常部署不需要，留着是为了排障时能知道
`install.bat` 到底替你做了什么，以及它在某台机器上跑不起来时怎么手工接着做。

### 1. 装 Python
装 **Python 3.9 以上**（开发机 3.9、门店实测 3.14，勾选 *Add to PATH*）。

> **Windows 7 只能用 3.8.10**：3.9 起 CPython 依赖 `api-ms-win-core-path-l1-1-0.dll`，
> Win7 上没有这个 DLL，安装包直接起不来（bugs.python.org/issue40740）。
> 3.8.10 是**最后一个支持 Win7 的版本**：
> <https://www.python.org/downloads/release/python-3810/>

> `install.bat` 会自己 `pip install -r requirements.txt`，**不用**手工装依赖。
> 手工装是这一条：`pip install requests pyyaml openpyxl`。
>
> **找不到 Python 时** `install.bat` 会停下来，把 `where python` / `where py`
> 的结果全打出来 —— 十有八九是装 Python 时漏勾了 *Add to PATH*。
> 最坑的是 Microsoft Store 那个 `python` 存根：它只会弹商店窗口，不是真 Python。

> **不需要装浏览器驱动**。自动抓 cookie 走的是浏览器自带的调试接口
> （用的还是 Python 标准库）。
>
> **用哪个浏览器**：装了 Chrome 就优先用 **Chrome**，没装才用 Edge（Windows 自带）。
> Chrome 优先是因为 Edge 从管理员进程启动时自我降权重启更凶，抓会话容易被掐断。
> 想换成 Edge：config 里加 `browser: {prefer: [edge, chrome]}`。
> ⚠ 换浏览器等于换一套登录态，**要重新登录一次华为**。

### 2. 复制项目
把整个 `cbg-reconcile` 目录拷到门店电脑，比如 `D:\cbg-reconcile`。

### 3. 改配置（**只有三行**）
编辑 `config\store-SCN231409.yaml`：

```yaml
store_code: SCN231409        # 这家店的华为门店编码
marker: Y                    # 串号标识里的本店码（对照 config/stores.yaml）
erp_store_name: 青岛新业广场店  # 云商里的门店名
```

> 华为门店编码不知道就**留空** —— 接口会按会话自身的门店查询。

### 4. 配云商账号
新建 `.secrets\erp.env`（或直接用 `~/.dsh/secrets/erp.env`）：

```
ERP_USERNAME=你的账号
ERP_PASSWORD=你的密码
ERP_COMPANY_CODE=00001937
```

### 5. 登录一次华为账号

```bat
python -m src.cli auth --auto
```

会弹出浏览器窗口 → 在里面登录华为账号 → 登录完成后 cookie 自动被抓走，窗口自动关闭。
**这一步一台电脑只需要做一次**（SSO 过期了再来一次）。

> 控制台「会话」页里有同一个按钮（「打开浏览器抓取」），**正常走界面就行** ——
> 门店同事不用碰命令行。会话是按店存的（`.secrets/cbg-<门店码>.json`），
> **换店等于换一份会话**，得用那个店的账号重新抓一次。

### 6. 试跑

```bat
python -m src.cli check --days-ago 1
```

### 7. 建计划任务
新建 `run.bat`：

```bat
@echo off
cd /d %~dp0
python -m src.cli check --days-ago 1 >> out\run.log 2>&1
```

注册每天 21:00 执行（界面上「设置 → 定时执行」也能一键注册）：

```bat
schtasks /create /tn "CBG报量对账" /sc daily /st 21:00 /tr "D:\cbg-reconcile\run.bat" /f
```

> 界面上注册完会**列出这台电脑上所有对账任务**，每行一个「删除」——
> 删的是**你点的那一行**，不是全部。想一天跑两次就换个**任务名**再注册一个
> （同名再注册是覆盖，不会变成两个）。

> 计划任务只管"几点跑对账"，**不管控制台**。控制台的开机自启：
> **`install.bat` 装完依赖会问一句**（回车即开），也可以随时在
> 「设置 → 后台服务」里开，或 `python bootstrap.py autostart`。
>
> 开机自启注册的是**登录触发的计划任务**，`RunLevel=HighestAvailable` ——
> 也就是**以管理员身份运行，而且不弹 UAC**。
>
> ⚠ **注册这一步需要管理员权限**（Windows 的安全边界，绕不过去）。所以点「是」之后
> 会弹**一次** UAC，之后每次开机都不会再弹。没给权限的话会退回注册表 Run 项 ——
> 功能仍可用，但服务是普通权限，界面上的「后台服务」卡片会**明确标出来**。

> **时间点选店里肯定开着机的时候**（门店一般设**晚上关门前**，比如 21:00）——
> Windows 计划任务错过时间**不会补跑**，设在半夜或清晨容易整天不跑。
>
> **选「昨天」还是「今天」**：
>
> | | 好处 | 代价 |
> |---|---|---|
> | **昨天**（默认） | **零遗漏**：那天的销售早就全部发生完了 | 发现漏报晚一天 |
> | 今天 | 当晚就能发现漏报，来得及让店员补 | **跑完到打烊之间的销售不在这份报告里**（会出现在次日那份里） |
>
> 云商按*支付时间*、华为按*建单时间*记时间，跨零点的情况门店本来就少，
> 所以 `report_lookahead_days` 默认 0（只看当天）。

### 8. 会话过期怎么办 —— 绝大多数情况不用管

华为 SSO 会话会过期（通常几天到几周）。**过期时工具会自己开一个无头浏览器，
从 profile 里把新 cookie 取回来**（`session.auto_refresh: true`）—— 全程无人工。

只有 **SSO 本身也过期**了（profile 里也没登录态）才会失败，那时：

* 明确打印 `❌ 需要人工登录一次`
* 退出码 `1`
* **绝不返回空差异**（空差异最危险：看起来"今天全报量了"，其实根本没查成）

处理：点一下界面上的「打开浏览器登录」，或者跑 `python -m src.cli auth --auto`。

### 9. 怎么知道对面跑的是哪一版

**这一行一定要会念** —— "我明明修好了 / 你那边怎么还报这个"就是靠它一轮说清的。

控制台标题下面、`selftest.bat` 第 0 节、`/api/health` 里都有：

| 显示成什么 | 说明是哪种装法 |
|---|---|
| `v1.2.0 · 2026-09-15 15:14` | 正式包（`BUILD.txt` 是打包时写的时间戳） |
| `v1.2.0 · GitHub main · v1.2.0` | 点过「检查更新」自更新过来的 |
| `v1.2.0 · git main@d0b9f80` | `git clone` 的目录（`install.bat` 从 `.git` 读的） |
| `v1.2.0 · 源码运行（未打包）` | 既没有 `BUILD.txt`、也没有 `.git` —— 拷来拷去的源码 |

优先级是 **`BUILD.txt` > `.git` > 「未打包」**：打包和自更新写的时间戳更权威，
不会被开发机的 commit 顶掉。

## 对账规则

```
云商当日销售
  ├─ 串号标识含本店码（忽略大小写 —— 顺和汇在数据里是小写 s）
  ├─ 卖出店 = 本店            → 纳入 ✅
  ├─ 卖出店 = 其他体验店       → 跳过（体验店之间走调拨，由买入店报量）
  ├─ 卖出店 = 非体验店         → 纳入 ✅ ← 核心场景
  └─ 退货 / 核销               → 跳过

华为当日订单（payStatus=2）→ 逐单取详情 → SN 集合

差集 → 未报量清单
华为有、云商该管销售里没有 → 反向差异
```

### 反向差异：**不做过滤，只用来看调拨货有没有出库**

反向差异 = 华为那边报了量、但云商"该本店报量的销售"里找不到的机器。
典型来源就是**别的店调拨过来的货**：货是别人的标识，卖在本店、报量也挂在本店名下。

| 类型 | 含义 | 门店要做什么 |
|---|---|---|
| **调拨进来** | 串号标识属于**其他体验店**（如 `LH,新`） | 核对「云商出库」那一列 |
| **来源不明** | 标识不是任何体验店（`J`/`jc`/`外调`…），或云商查不到 | 人工查一下 |

报表里每条都带**云商侧那一行**，直接看「云商出库」列：

* `✅ 已出库` + 卖出店/单号/金额/时间 → 正常，货确实卖了
* `⚠️ 查无出库记录` → **要问一句：货呢？**（报了量但云商没这笔销售）

> 这里踩过一次弯路：一开始把「体验店之间」的反向差异**过滤掉**了。
> 但门店其实需要它来核对调拨货出库 —— **有用就带着上下文报出来，而不是一刀切掉**。
> 现在只分类、不丢弃，控制台和 KPI 里单独统计「调拨货查无出库」。

体验店名单和串号标识映射在 `config/stores.yaml`，**那是唯一真源**，改那里。

| 9c | **给用户指版本号要按系统给，别一律说"装最新版"** | 原先四个 `.bat` 和 `bootstrap.py` 都写死"装 Python 3.14"，而 **Win7 上 3.9 以上根本装不上** —— 门店照着做会卡在安装包报错上，然后就没有下文了。现在 `bootstrap.py` 的 `needs_python_help()` 会看 `is_win7()` 分开说，bat 里的 `FIX` 段则不再点名具体版本（bat 是纯 ASCII 的，判断不了系统） |
| 9d | **`from __future__ import annotations` 在这项目里是功能，不是风格** | `bootstrap.py` 里 `def missing() -> list[str]` 是 PEP 585（3.9+）。没有那行 future import 时，注解在 `def` 那一刻求值 → **3.8 上 import 本文件直接 `TypeError`**，而 `check_python()` 那句"版本太旧，请装 X"根本来不及打印。也就是说**那段友好提示在任何能触发它的解释器上都到不了** —— 3.8 及以下全都会先炸在这一行。测试抓不到（测试跑在 3.9+ 上，那时 `list[str]` 求值正常），是靠真装了个 3.8 才发现的 |
| 9f | **别让服务以管理员身份跑 —— 它会把「自动抓会话」弄坏** | 服务是管理员 → 它拉起的 Edge / Chrome 也是管理员 → 浏览器（Chrome 138 起）**拒绝以管理员运行**：进程把命令行交棒出去就自己退 0，`--user-data-dir` / `--remote-debugging-port` 落不到活着的实例上，调试端口永远没人监听。实测报「Edge 启动后立刻退出（退出码 0）」，**链接还跑到了用户原来那个浏览器里**。所以 2026-09-16 起**默认改成普通权限**：开机自启写 `HKCU\...\Run`（任何用户都能写，一次 UAC 都不弹），装机那一次 UAC 取消了。`_win_install(elevated=None)` **不许再猜当前进程**（以前是 `is_elevated()`，从提权进程里调就静默注册成管理员模式） |
| 9e | **一台电脑上可能有两个 Python：装到 A、却用 B 启动** | 依赖装进 `install.bat` 当时探测到的那个 Python，而 `start.bat` 每次是重新去 PATH 上找的 —— 找到另一个就报 `ModuleNotFoundError: No module named 'requests'`，看着像"当初没装成功"。现在安装成功时把解释器写进 `.secrets/python.txt`（**带引号**一行 + 版本号一行），五个 `.bat` 用 `set /p` 读它、`src/runtime.py` 给 `autostart` / `schedule` / `cli` 读它。放 `.secrets/` 是因为它属于 `selfupdate.NEVER_TOUCH`，**升级不会冲掉**。记录里的路径没了就自动退回探测 PATH |

| 10 | **未登录时 cbg 也发 `JSESSIONID`** | 所以"cookie 名字齐了"不能当登录判据，只能靠 `ping` 自检。抓 cookie 时**必须验证通过才落盘**，否则一次失败的续期会覆盖掉还能用的会话 |
| 11 | **别去解密浏览器的 cookie 数据库** | Chrome 127+ 有 App-Bound 加密，版本一升就废。走 CDP 让我们自己的浏览器把 cookie 交出来 |

| 38 | **每行任务要能单独"执行"** | 用 `schtasks /run` 而不是直接调 `check` —— 这样验证的是**任务本身**（路径、参数、权限对不对），而不是"代码没问题"。后者才是用户想确认的 |
| 39 | **run 脚本不能在 bat 里重定向输出** | `>> out\run.log 2>&1` 让屏幕上**一片空白** —— 手动双击的人看到的是"黑窗口 + 一分多钟 + 自己关掉"，反馈就是**"什么都没发生"**（门店实测）。改成 Python 侧分流（`check --log-file`），屏幕和文件两边都有；再配一个跑完停住的 `run-now.bat` 给人用 |
| 40 | **tee 必须每行刷盘** | stdout 重定向到文件是块缓冲，进程被 kill / 卡住 / 崩了缓冲区整个丢掉 —— 而计划任务日志的意义就是"出事之后还能看"。实测：跑了一分钟，`out/run.log` **0 字节**。⚠ 测这个必须用**真文件**，`StringIO` 不缓冲、测不出来（第一版就是这么写的，把 flush 删掉测试照样绿） |
| 41 | **退出码 21 = "进程立刻退出了"，不是提权专属** | macOS 上复现了：一个**残留的 Edge 占着 profile**，之后每次启动都退 21。这个坑会**连锁** —— 上次抓取失败时浏览器没关掉（拿不到句柄），它会一直占着，之后全部失败。所以 `launch()` 失败时会**检测 `SingletonLock`** 并把"profile 被占着"排在原因第一位 |
| 42 | **卸载默认不删数据** | `--yes` 只跳过"确定吗"，删报告和凭据必须单独 `--purge`。（第一版 `--yes` 连数据一起删 —— 真跑时把自己的 `out/` 删了。）删 `.secrets/` 还可能撞上正在跑的进程 → ENOTEMPTY，所以重试一次并把失败原因报出来，不假装成功 |
| 43 | **状态提示不能写死在前端** | 会话页那句"没验证过"曾经是**硬编码字符串** —— 点完自检横幅纹丝不动（用户报的）。现在分三种状态渲染，而且**自检结果要落盘**（`.secrets/session-check.json`），否则刷新页面又变回"未验证" |
| 44 | **自检记录要跟会话绑定** | 记录里存会话 cookie 的指纹。**换过会话（重新抓/重新导入）后旧记录自动作废** —— 拿旧会话的"✅ 通过"给新会话背书，比不显示更糟。前端判断不了这个（它只看到"没有记录"），所以由后端给 `check_stale` |
| 45 | **计划任务是个黑盒，界面必须把日志捞出来** | 点「执行」走的是 `schtasks /run`，另起一个进程 —— 界面上什么都看不到。于是"点了也不推送"成了唯一能观察到的现象（用户报的），其实日志里写着 `企微：跳过（本次无差异）`。`/api/runlog` 把日志 tail 出来，并把"推没推、为什么没推"单独挑出来显示 |
| 46 | **推送结果要逐行保留记号** | 整块染绿的话，"邮件跳过"也会跟着变绿，反而误导。✅/跳过 各自带自己的记号，整块用中性底色 |
| 47 | **服务起的每个控制台子进程都要 `CREATE_NO_WINDOW`** | 服务是 `pythonw.exe`（无控制台）。这时起 `schtasks` / `tasklist` / `python -m src.cli` 这类**控制台程序**，Windows 会给它**新开一个黑窗口** —— 用户看到的就是"操作时弹出来的黑窗"。任务列表每 30 秒刷一次、每次好几个 schtasks，不处理会一直闪。判断用 **`os.name == "nt"`**，别用 `platform.system()` —— 后者是模块属性，测试里一 patch 就全局生效，会在 macOS 上也塞 creationflags 直接崩（真踩过） |
| 48 | **计划任务的 bat 不能同步等进程** | `schtasks` 起 cmd 跑 `run.bat` 时会开一个 cmd 黑窗；同步等 `python.exe` 的话它会**挂满整个对账过程**。改成 `start "" pythonw.exe …` —— cmd 立刻退出（只闪一下），pythonw 自身无控制台。代价：bat 拿不到退出码了，所以**改由 Python 自己往日志写 `结束 exit=N`**（界面靠这行判断"跑完了没"）。手动那个 `run-now.bat` 反过来，**必须同步**，否则跑完立刻 pause 等于废了 |
| 49 | **生成的脚本会在门店电脑上"卡住不动"** | `run.bat` 只在**注册任务时**生成，升级代码**不会**动它 —— 于是"我明明修好了，门店跑的还是旧的"（用户真踩到：日志格式还是旧的、黑窗没修掉）。脚本里带 `RUNNER_MARK`，设置页打开时比对，过时就按当前模板**自动重建**，并且**保住用户原来选的 `--days-ago`**（默默改掉对账目标日比不重建更糟） |
| 50 | **退出码不是万能的，要看"跑起来没"** | 用户报"退出码 120"，而 120 不在我们任何约定里 —— 光看退出码指不到方向。真正有用的是**日志里有没有对账输出**：只有退出码、一行输出都没有 → 说明对账程序**根本没执行**（run.bat 里路径不对 / 假 python），跟"对账失败"是两回事，给的建议也完全不同 |
| 51 | **`pythonw` 连 stderr 都没有，启动失败会静默** | `pythonw.exe` 是 GUI 子系统程序：`sys.stdout` / `sys.stderr` **就是 `None`**。所以只要在 `import src.cli` 那步挂了（缺依赖、假 python、路径不对），**traceback 一个字都留不下来**。实测就是日志里只有 `exit=120`、没有任何对账输出。修法：`run_check.py` 兜底启动器 —— **先开日志、把 stdout/stderr 接过去，再去 import**。并且 `start` 之后不能无条件 `exit /b 0`（那样启动失败也静默） |
| 52 | **排查工具不能依赖被排查的东西** | `diagnose.bat` 是纯批处理、**不需要 Python** —— 因为要查的很可能就是"Python 没装好"，那时任何 Python 脚本都跑不起来。它把 `where python`、依赖、`run.bat` 全文、日志、任务列表、以及**真跑一次的完整报错**一起落成文件 |
| 53 | **只认 `python` 会误判"没装 Python"** | 装了 Python 但没勾 `Add python.exe to PATH` 时，`python` 用不了、**`py` 启动器还在**。只探 `python` 会拦住明明装好了的用户，还叫他去重装。所以每个 bat 都是 `python` → `py -3` 两级探测，并且用探到的那个跑（`%PYBIN%`）。⚠ 探测块后面**必须**有 `exit /b`，否则正常跑完会**穿透**进 `:nopython` —— 装成功了还打一遍"找不到 Python"，用户看到的就是"成了怎么还让我按回车" |
| 54 | **门店配置可以启动后再改，而且必须立刻生效** | 改 `store_code` 只换 `config/` 里三行，界面「设置 → 门店」就能改，读配置是**每次请求现读**的，所以不用重启。⚠ 但**会话文件是按店存的**（`.secrets/cbg-<门店码>.json`）—— 换店等于换了一份会话，得用那个店的账号重新登录 |
| 55 | **自检记录要把门店算进指纹** | 自检 = "拿这份会话去查**配置里那个门店**"。只按 cookie 算指纹的话，改了门店之后旧记录还会被当成有效 —— 从"没权限的店"改成"有权限的店"会白报没过，反过来更糟：**说过了但其实查不了**。指纹里加上 `store_code` |
| 56 | **浏览器被强制 `UserDataDir` 时，`--user-data-dir` 会被直接忽略** | `UserDataDir` 是 Edge / Chrome 的**强制策略**（一般是域 / 组策略推的，换浏览器或重装都没用）。设了它，浏览器就不再理会命令行给的独立目录，而是开在**用户日常那个 profile** 里 —— 我们等的调试端口永远没人监听，报「启动后立刻退出（退出码 21）」或链接跑到别的窗口。⚠ 门店实测查了好几轮权限 / profile 残留 / 版本都不对，最后是用户自己找出来的。`browser.forced_user_data_dir()` 现在会读注册表提前硬失败 —— **不能"将就用那个被强制的目录"**，那等于去读用户日常浏览器的 cookie |

## 目录结构

```
cbg-reconcile/
├── config/
│   ├── stores.yaml            # 14 家体验店 + 串号标识映射（唯一真源）
│   └── store-SCN231409.yaml   # 本机配置
├── src/
│   ├── session.py   # 从 curl 解析 cookie + csrf（退路走这里）
│   ├── cdp.py       # 极简 CDP 客户端（标准库 WebSocket，无依赖）
│   ├── browser.py   # 自动抓 cookie：起浏览器 → 读 cookie + csrf
│   ├── cbg.py       # 华为取数
│   ├── erp.py       # 云商取数（自带最小实现）
│   ├── reconcile.py # 对账规则（纯函数 —— 改规则只动这里）
│   ├── report.py    # Excel + 控制台输出 + 报告摘要 json
│   ├── config_io.py # 配置读写（定点替换，保留注释）
│   ├── schedule.py  # 定时执行（Windows schtasks / unix crontab）
│   ├── service.py   # 后台服务：状态文件 / 探活 / 停止
│   ├── lockfile.py  # 跨进程锁（防两个对账同时跑，云商不能并行登录）
│   ├── autostart.py # 开机自启（注册表 / LaunchAgent / autostart）
│   ├── runner.py    # 后台跑对账 + 日志缓冲
│   ├── web.py       # 本地控制台服务（标准库）
│   ├── xlsx_io.py   # xlsx 读写（不信 dimension）
│   └── cli.py       # 命令：auth / ping / check / serve
├── bootstrap.py     # 四个 .bat 的统一入口（纯标准库 —— 装依赖前它就得能跑）
├── boot.py          # 开机自启的入口（不弹窗）
├── web/             # 前端（原生 HTML/CSS/JS，无构建）
│   ├── index.html · app.js · style.css
├── tests/           # 210 个单测，夹具是 2026-09-14 的真实数据
└── out/             # 差异清单 + 摘要 json + 日志
```

跑测试：

```bash
python3 -m unittest discover -s tests -t .
```
